# TSMC Careers (careers.tsmc.com)

Verified live 2026-10-31 and 2026-11-01 (English UI, `en_US`). The platform looks like Avature: `SearchJobs`, `JobDetail?jobId=N`, numeric form field names.

- **Auth**: log in by hand. When logged in the header shows the candidate name and a "My Profile" link. Nothing here stores or types credentials.
- **URLs**: `/en_US/careers/Profile` (read-only view, file Download/Delete, "Positions Applied" with "Update Application"), `/en_US/careers/ProfileEdit` (one long form, buttons `Cancel` / `Save`), `/en_US/careers/SearchJobs`, `/en_US/careers/JobDetail?jobId=<n>`. A permanent "Register your profile on TSMC Talent Pool" posting exists as a job detail.
- **Data model** (what the profile has): Personal Information, Resume Keywords, Work History rows, Education rows, Attachments. **There is no free-text description per job, no skills list, no summary.** The resume file is the only place for achievements, so keep the PDF current.
  - Personal: last name, first name, cell phone, second phone, email, second email, mailing address (single text field).
  - Resume Keywords: four free-text inputs, each a comma/、-separated list (used for TSMC's resume search). Several hundred characters are accepted per input.
  - Work History row: company (a `<select>` of known companies, not free text; an unlisted company shows a free-text input instead), location, job title, employment type, current employer yes/no, From/To as `<input type="month">` (`YYYY-MM`).
  - Education row: school (`<select>`), education level (`<select>`), major (free text), graduated yes/no, From/To months.
- **Field names** are `<formId>-<fieldId>-<rowIndex>` (seen as `3190-2-0` = work history, job title, row 0; `3188-1-<n>` keywords; `3192-1-<n>` major; `file_3194` resume). Ids may differ per tenant or after a redesign: find fields by label first, fall back to names.
- **Attachments**: all files together must stay under 30 MB; avoid uploading duplicates. Slots: Resume, Transcript of highest degree, Transcript of second-highest degree, Cumulative GPA, Language Proficiency Certificate, License / Certificate, Others (two). None blocks saving. Several resumes are allowed (for example one per language).
  - Slot input names seen: `file_3194` Resume, `file_3195` transcript of highest degree, `file_3263` transcript of second-highest degree, `file_3264` cumulative GPA, `file_3196` language certificate, `file_3197` license / certificate, `file_3265` and `file_3198` Others. Match by the label text above each input if the numbers change.
  - Upload: in `ProfileEdit`, `input[name="file_3194"].setInputFiles(<pdf>)`, then `Save`. Non-ASCII file names (for example Chinese) upload fine; an image-only (scanned) PDF is accepted. The slot takes one file per save; repeat the visit to add another. Saving redirects to `/Profile`.
  - Delete: only on `/Profile`, link `Delete` next to a file. It opens a native `confirm()` dialog: register `page.on('dialog', d => d.accept())` before clicking. Reload to verify ("No attachments found").
- **Saving**: about 30 inputs are `required`; a profile that was complete before still saves. A failed save stays on `ProfileEdit` with inline errors.
- **Recipe: refresh the profile from a resume**: update the keyword inputs and any changed title/major/date fields in `ProfileEdit`; `node scripts/resume-pdf.mjs`; delete old resume files on `/Profile` (dialog); upload the new PDF(s) in `ProfileEdit`; reload `/Profile` and compare.
- **Dead ends**: looking for a work-description or skills field (does not exist). Deleting from `ProfileEdit` (only the "Uploaded files" dropdown is there; deletion needs `/Profile`).

## Search and discovery (verified 2026-11-01)

- **No login needed, but a Cloudflare check blocks plain HTTP clients**: Node's `fetch` gets 403 "Just a moment". `lib/http.mjs` falls back to a fetch inside a page of your Chrome (`attach: cdp` in `browser.yml` uses one extra tab of the Chrome you started, closed at the end). After the first block the host is remembered, so only the first request tries Node.
- **List**: `GET /en_US/careers/SearchJobs/?<filters>&listFilterMode=true&jobRecordsPerPage=10&jobOffset=<n>`. The page size is fixed at 10 (larger values are ignored); the total is in the text "N results". The form posts, but the same parameters work as GET and the paging links keep them.
- **Filters** (ids are in `adapters/tsmc.mjs`): `search` keyword, `1277` location, `147` job type (Technician / Associate Engineer / Engineer / **Manager / Executive**), `558` job category, `542` employment type, `4177` organization (TSMC Group, ESMC, JASM). Location is country-level only ("Taiwan"); the work site (for example Hsinchu) shows up, when at all, inside the posting text.
- **Best filters for manager-level searches**: job type "Manager / Executive" plus Location Taiwan, then category "Information Technology", then a few keywords (director, program manager, software). The unfiltered list is about eight hundred postings across all functions, most of them fab, legal, HR and finance.
- **List item**: `article.article--result`; link `JobDetail?jobId=<n>`; subtitle spans `list-item-location`, `list-item-careerArea`, `list-item-employmentType`, `list-item-posted`. The standing "Register your profile on TSMC Talent Pool" posting leads unfiltered lists and is not a job (the adapter skips it).
- **Detail page**: read the `.article__content__view__field` label/value pairs: Company, Location, Career Area, Job Type, Employment Type, Posted, Job Responsibilities, Job Qualifications. Dates are English month names ("Sep 11, 2026"): build the ISO date from the parts; `Date.parse` + `toISOString` is one day early in UTC+8.
- **Cost**: about 4 s per detail page through the browser (a hundred postings take roughly eight minutes) and about 1 s per list page after the polite delay. Filter first; do not fetch everything.
- **Duplicates with your own history**: `/Profile` lists "Positions Applied". Check it before recommending a posting; a posting you already applied to scores like any other but must be marked.
- **Dead ends**: `jobRecordsPerPage` above 10 (ignored); Node `fetch` without the browser fallback (403); the JSON-LD `JobPosting` block (its responsibilities, qualifications, work-hours and skills fields repeat the same text shifted, and `datePosted` is null).

## Applying (verified 2026-11-01)

- **Entry**: the detail page's `Apply` link is `/en_US/careers/ApplicationForm?jobId=<n>&source=External%2BCareer%2BSite`. Opening it does not create anything; `Save as Draft` does. After a submit the site shows `/Success?jobId=<n>` ("Thank you …") and `/Profile` lists the posting under "Positions Applied" with the date.
- **Three steps in one page, buttons `Previous` / `Continue` / `Submit` (last step only)**. Step 1 personal information and essays, step 2 work history / education / language / licences / attachments, step 3 reference check.
- **The form is pre-filled from your previous application, not only from the profile**: identity, a referral (name / relation / department), the essays, every work-history "Major Achievement", the reference people. Read them before continuing: stale facts and wording addressed to an earlier posting are the main risk.
- **Step 1 fields** seen: name, passport name, nationality (select2), national id, phones, emails, mailing address, preferred work regions (checkboxes), referral rows `3001-<1..3>-<row>`, military status, "worked at TSMC before" (required), **how did you learn about the position** (required; see below), three free-text essays `3012` (required self-introduction), `6002` (competitive advantages and areas to improve), `6003` (most frustrating and most proud experience), four keyword inputs. Textareas have no length limit.
- **Select2 widgets** (nationality, "how did you learn"): the underlying `<select>` has no options until opened. Click `select[name="3004"] + .select2-container`, type the wanted text into `.select2-search__field`, click the exact `.select2-results__option`. `selectOption` on the hidden `<select>` times out.
- **Step 2**: work-history rows `3017-<field>-<row>` (job title `2`, employment type `12`, company `20`, location `9`, current `6`, from `4`, to `5`, salary `15`/`16` optional, **Major Achievement `11`**, reason for leaving `26` required for past jobs). Education `3019-*` (includes thesis and rank fields). Language rows `3021-*`. A blank **language-certificate row `3023-*` is added automatically and then demands a score and a test date**: click its `Remove` if you have no score, or `Continue` fails with "Language Proficiency Score: This field is required". Licences `3025-*` and achievements `3027-*` blank rows are optional and do not block.
- **Attachments in step 2**: the "Uploaded files" dropdown (`#fileInput_3029_oldFilesSelector`, an id, not a name) only lists the files already in the profile; they travel with the application. Uploading again creates duplicates; use `/Profile` to manage files.
- **Step 3**: reference check, at least two people, one a supervisor or teacher; rows `3036-<1..6>-<row>` (name, relationship, company, title, email, phone). They are third parties: confirm they still agree before submitting.
- **Validation** appears only on `Continue`/`Submit`, as a banner "There are some errors" plus per-field messages; it stays on the same step.
- **Dead ends**: choosing a resume from the "Uploaded files" dropdown (it is a list, not a selector); `selectOption` on select2 selects; trusting pre-filled essays (they name the previous posting).
