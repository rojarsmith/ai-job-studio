# 104 人力銀行 (104.com.tw)

Verified live 2026-10-31 on the resume editor (`pda.104.com.tw`), Traditional Chinese UI.

- **Auth**: log in by hand in the attached Chrome. Do not script login here; Cloudflare challenges the search API (see the adapter).
- **URLs**: resume editor `https://pda.104.com.tw/profile/edit?vno=<resume id>` (the id is per person; find it from the open tab via `scripts/tabs.mjs`).
- **Layout**: one long page, sections in a left rail (個人資料, 學歷, 工作經歷, 求職條件, 語文能力, 專長, 資格認證, 專案成就, 附件). Edits open inline over the section, with `取消` / `儲存`. Cards from several sections can be "open" at once; click save on the one you edited (the last `儲存` button in the DOM is the open one).
- **Edit icon**: `i.jb_icon_edit` inside each item. For a given item, go up with `xpath=ancestor::*[.//i[contains(@class,"jb_icon_edit")]][1]` from a known text node, then click its icon. `新增` is a leaf element; pick the one whose nearest `[class*=form-element]` text starts with the section name.
- **Rich text** (job description, 專長與技能, 工作內容 inside 求職條件, project description) is a Quill editor, `.ql-editor`. Scope to the open form: `//button[normalize-space()="儲存"]/ancestor::*[.//div[contains(@class,"ql-editor")]][1]//div[contains(@class,"ql-editor")]`. Click, `Control+A`, `Delete`, then `keyboard.insertText(line)` per line with `Enter` between lines; an empty line between bullets renders as a blank line. Many `.ql-editor` nodes exist at once (read-only previews count): never use a bare `.first()` outside the scoped form.
- **Photo**: 個人資料 edit → click `.avatar` → dialog "上傳圖片" with one hidden `input[type=file]` (the visible button does not raise a file chooser: use `setInputFiles` on the input) → crop dialog → `儲存` → then save the personal-data form. Best size 360×360, JPG/PNG.
- **Project (專案成就)**: a new item needs only a name; fields: type radio (upload / video link), name, start/end year-month, "still ongoing", description (Quill), link (`input[placeholder="https://"]`).
- **Do not overwrite blindly**: 求職條件 holds expected salary, location and role choices that the user set deliberately.
- **Dead ends**: `getByRole('button', {name:'上傳照片'})` raises no file chooser. Reading `document.body.innerText` of this page costs thousands of tokens: slice by section.

## Search and discovery (verified 2026-11-01)

- **No login needed, but Cloudflare challenges plain HTTP clients.** `lib/http.mjs` falls back to a fetch inside a page of your attached Chrome (`attach: cdp`) and remembers the host; this path was run live and works.
- **Cost**: about two minutes for eighteen keyword/area searches, about 4 s per detail page. Fetch details only for rows that pass the title screen.
- **Scale (2026-11-01)**: 24 keywords × 5 areas × 3 pages returned about 3600 rows in 17 minutes (about 6 minutes for 21 keywords × 2 areas). Redirect the output to a file or run it in the background: piping through `tail` shows nothing until the end. Of those rows about 90 % fail the title screen and about 7 % are not listed, so a wider search adds only dozens of new rows.
- **Area codes are by posting address**: New Taipei, Hsinchu and Taichung postings come back under a Taipei or Kaohsiung search too. Check `location` against the profile's allowed cities before spending a detail fetch or a score.
- **Noisy keyword**: "CTO" matches "CTO Office" research roles (scientists, IC engineers). Add `scientist|研究員|analyst` to `title_exclude`.
- **Results are noisy**: broad keywords (project manager, director, AI) return beverage, medical, construction and hardware R&D roles. Set `title_include` (every entry must match) and `title_exclude` (any match drops) per source in `portals.yml`; after tightening them run `node scripts/discover.mjs --rescreen` to drop rows that no longer pass. Keep "engineering" in the include family or "Director of Engineering" is lost.
- **Report fields** (adapter output): company, title, location, salary text, posted date, description, and a Requirements block (experience, education, major, languages, skills, tools, other). Pay is often "面議" (negotiable) or monthly; compare against the annual expectation in the profile before scoring, and score unknown pay as 3.
- **Level**: most postings ask for 3–5 years and carry a project/product manager title. Only a minority (head, director, 研發主管, CTO, AVP) match a VP/Director target; scoring should cap level-mismatched rows at 3.
- **Scoring a large batch**: title screen → read full text only for plausible rows → write LLM scores for those → mark the rest `scored_by: triage` (score 1–2, skip), so the shortcut stays visible; then `score-apply.mjs` and `rank.mjs --source 104 --write`.
- **Dead ends**: Playwright `connectOverCDP(http://127.0.0.1:<port>)` timed out in this setup; connect to the `webSocketDebuggerUrl` from `/json/version` (done in `browser/launch.mjs`).
- **Searching by employer does not work through the job API**: a keyword that is only a company name returns `{"data":[],"metadata":{"companyKeyword":true}}`, and "company + role" keywords mix in unrelated employers. Do not loop over company names. Instead search by role, then keep only listed employers with `require_listed: tw` (see below).
- **Taiwan-listed filter**: `require_listed: tw` on the source drops postings whose employer is not on the TWSE or TPEx lists. The lists come from the exchanges' open data (`openapi.twse.com.tw/v1/opendata/t187ap03_L`, `tpex.org.tw/openapi/v1/mopsfin_t187ap03_O`, plain `fetch` works, no challenge), cached for a week in `generated/data/listed-tw.json`; 臺/台, legal-form suffixes and "English_中文" employer names are normalised (`lib/listed.mjs`). Judging "is it listed" from memory was wrong at least once (a small IT employer turned out to be on TPEx), so use the list.

## Applying (verified 2026-11-01)

- **Entry**: on `https://www.104.com.tw/job/<id>` the orange 應徵 control is a `<span>`, not a button or link (`getByRole` finds nothing). Click `locator('span').filter({hasText:/^應徵$/})` and pick the topmost visible one (several exist; do not filter by a fixed y: a company banner can push the real button below y=600). The URL becomes `?apply=form` and a modal opens; nothing is sent yet.
- **Modal**: 選擇履歷 (a select, default is the online resume), 自我推薦信 (select, default "系統預設") with a textarea (limit 2000, counter shown), checkboxes 儲存此次修改 and 新增自我推薦信, buttons 取消 / 確認送出. **The default letter is a one-line generic greeting**: replace it per posting with `Control+A`, `Delete`, `fill`. Leave the two checkboxes off so the saved default letter is not changed.
- **Submit**: 確認送出 goes to `/job/apply/done/?jobNo=<id>` ("應徵成功"). That page offers 取消應徵 for five minutes. Only click 確認送出 after the person said to send.
- **Dead ends**: `getByRole('button'|'link', {name:'應徵'})`; looking for an `<a>` or `<button>` text node of exactly 應徵.
